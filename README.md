# Eesti A2 — тренажёр форм + шпаргалка

Статичная PWA без фреймворков и без бэкенда. Работает офлайн, прогресс — в
localStorage браузера/телефона.

## Запуск локально

```bash
python -m http.server 8130 --directory eesti
```

Открыть http://localhost:8130. В Claude Code — просто preview `eesti`
(конфиг уже в `.claude/launch.json`).

Через `file://` не работает: service worker и `fetch` файлов требуют http.

## Что внутри

| Вкладка | Что делает |
|---|---|
| **Формы** | Даёт `nimetav` / `ma`-инфинитив, ты вводишь остальные основные формы. У глагола — ещё и основу отрицания (`ei loe`). Главный режим. |
| **Слова** | RU → ET (ввод) и ET → RU (самооценка «знал / не знал»). |
| **Микс** | Всё вперемешку. |
| **Экзамен** | Кнопка внизу: 20 заданий, таймер, счёт из 20. Подробности ниже. |
| **Шпаргалка** | Отрицание, вопросы, порядок слов, падеж объекта, императив, рекция, местоимения, даты, поздравления. Только чтение. |

Кнопки `õ ä ö ü š ž` под карточкой — с русской раскладки иначе не набрать.
Enter переходит к следующему полю, на последнем — проверяет. После ответа
показывается живой пример из словаря EKI.

## Экзамен

Кнопка внизу. 20 заданий, счёт из 20, таймер 15 минут, порог 60% — как на
настоящем экзамене. Подсказок нет, вернуться к заданию нельзя, разбор ошибок
с объяснением правила — только в конце. Результаты попыток пишутся в прогресс.

**Это две части из четырёх.** Лексика и грамматика — то, на чём держится
чтение. Аудирование и говорение сюда не входят: у EKI нет аудио, а устный
ответ некому оценить. Изображать их «для галочки» вреднее, чем не делать —
даст ложное ощущение готовности. Для них — материалы
[Harno](https://harno.ee/eesti-keele-tasemeeksamid): консультационное пособие,
образец аудирования, видеоразбор.

Задания двух сортов. Авторские (`data/exam.json`, 30 штук) — на правила из
шпаргалки: падеж объекта, отрицание, рекция, порядок слов, даты. Генерируемые
— из проверенного словаря.

Дистракторы: в заданиях на **формы** и на **отрицание** берутся из реальных
форм того же слова — иначе задание решалось бы угадыванием, не зная языка.
В заданиях на **перевод** это другие слова словаря, там такой тонкости нет.
На каждую попытку набор и порядок вариантов перемешиваются заново.

Вопрос про форму всегда называет число (`ainsuse osastav`): без этого
множественный партитив среди вариантов формально тоже был бы верным ответом.

Дописывать банк: `data/exam.json`, поля `q` / `ru` / `options` / `answer`
(индекс верного) / `why`. Варианты перемешиваются при показе, так что верный
можно всегда держать нулевым.

Письмо приложение не проверяет: экзаменные форматы — визитка от 25 слов и
сообщение от 30 — пиши и присылай, разберу по критериям.

## «Перевод» — словарь и переводчик

Кнопка внизу. Одно поле, куда можно вписать что угодно:

- **одно эстонское слово в начальной форме** → словарная статья EKI: все формы,
  русский перевод, рекция, пример. Тут же можно завести карточку;
- **словоформа, фраза или предложение** → перевод целиком;
- **русский текст** → перевод на эстонский, направление определяется само по
  наличию кириллицы.

Разница принципиальная: словарь даёт нормативные формы, машинный переводчик —
нет. Поэтому одиночное слово сначала ищется в словаре и только при неудаче
уходит в машину, а машинный результат всегда помечен как машинный.

Такие слова живут **внутри прогресса** (`state.words` в localStorage), а не в
`data/words.json`. Значит, они попадают в выгрузку бэкапа, но не в git. Если
слово должно доехать до репозитория — скажи, добавлю через `tools/sonaveeb.py`.

Перевод подставляется **из словаря EKI** (у него есть русская часть, она лежит
внутри значений). Если русского в статье нет — зовётся Neurotõlge
(`api.tartunlp.ai`, госпереводчик, без ключа) и результат прямо помечается как
машинный: на редких словах он врёт (`sügavkülmik` → «каучуковая бревна»).

Офлайн эта кнопка не работает и честно об этом пишет: формы берутся из словаря,
выдумывать их приложение не будет.

## Как добавлять слова

**Формы руками не пишем.** Они приходят из EKI (`api.sonapi.ee`, витрина
Sõnaveeb) через `tools/sonaveeb.py`. Наше дело — начальная форма и перевод.

Файл со словами, по строке на слово:

```
helistama — звонить — helistan
vann — ванна — vann
```

Третья колонка — форма, как она напечатана в учебнике. Она нужна затем, что
книга даёт слова в личной форме (`helistan`), а словарь понимает только
начальную (`helistama`). Начальную подбирает человек — и скрипт тут же
проверяет: если книжной формы нет среди форм словарной статьи, строка уходит
в отчёт, а не в словарь. Колонку можно опустить, тогда проверки не будет.

```bash
python tools/sonaveeb.py add words-new.txt
```

Остальные команды:

| Команда | Что делает |
|---|---|
| `check` | Сверяет весь `words.json` с EKI. Молчит, если всё сошлось. |
| `fix` | Переписывает формы по словарю, дозаполняет отрицание, прошедшее, nud-форму и рекцию. |
| `ru` | Сверяет наши русские переводы со словарными. Формы давно из EKI, переводы были единственным непроверенным местом. |
| `show lugema` | Показывает, что словарь знает про слово. |

Ответы кэшируются в `tools/.cache/` (в git не идёт), при 429 скрипт
отступает и повторяет.

## Слова из учебника

`tools/book.py` разбирает «Eesti keele sõnavihik A2» на поурочные списки:

```bash
python tools/book.py list sonavihik.pdf
python tools/book.py dump sonavihik.pdf 12.1
```

**Сам PDF в репозиторий не кладём** — учебник под копирайтом
Kultuuriministeerium. Скрипт работает с локальной копией, в git едут только
слова и наши переводы.

У восьми уроков (3.4, 4.4, 7.5, 13.2, 14.2, 15.2, 21.4, 23.2) списки
нарисованы картинками — оттуда текст не извлекается, эти уроки заводятся
вручную.

Многословные выражения (`pesen hambaid`, `akna all`) в карточки форм не
годятся — их место в шпаргалке `data/grammar.json`, структура
`sections[].rows[]` с полями `et` / `ru` / `hint`.

Через запятую в поле формы — равноправные варианты из словаря
(`tube,tubasid`), тренажёр примет любой.

## Алгоритм повторений

SM-2 lite. Ответил верно → интервал 1 → 3 → ×ease (ease растёт до 2.8).
Ошибся → интервал в ноль, ease −0.2, карточка возвращается через три позиции
в этой же сессии. Лимит новых карточек в день — в настройках, по умолчанию 12.

## Деплой

Приложению нужен адрес в сети: с `localhost` телефон его не увидит, а
service worker и установка требуют https (исключение — только localhost).

**GitHub Pages** — быстрее всего, ничего ставить не надо:
Settings → Pages → Source: Deploy from a branch → `main` / `/ (root)` → Save.
Через пару минут поднимется `https://<логин>.github.io/eesti-keel/`.

**Cloudflare Pages** — если нужен свой домен: Workers & Pages → Create →
Pages → Connect to Git, build command пустая, output directory `/`.

## Установка на телефон

**Android (Chrome).** Открыть адрес → меню «⋮» → «Установить приложение».
Chrome предложит установку сам, если выполнены его условия: манифест,
`display: standalone`, иконки 192 и 512, активный service worker, https —
всё это есть. Иконка с `purpose: maskable` нужна, чтобы лаунчер не обрезал
её по своей маске и не подкладывал белый круг.

**iOS (Safari).** Автоматического предложения нет: «Поделиться» → «На экран
Домой». Ставить именно так важно — установленному приложению iOS не чистит
localStorage через неделю простоя, а вкладке Safari чистит.

После установки приложение открывается офлайн; онлайн нужны только
«Перевод» и добавление слов, потому что формы берутся из словаря.

**Тема** берётся из системной автоматически (`prefers-color-scheme`), своей
кнопки переключения нет. Цвет строки состояния объявлен двумя `theme-color`
с медиазапросами — с одним фиксированным над светлым приложением висела
тёмная полоса.

**Прогресс у каждого свой** и лежит в браузере конкретного устройства.
Двое могут учиться по одному адресу независимо; между своими устройствами
переносить через «Настройки → Выгрузить / Загрузить прогресс».

**После правки файлов подними `CACHE` в `sw.js`**, иначе на телефоне
останется закэшированная старая версия.

Два места, где это уже ломалось (не убирай `cache`-опции, они не украшение):

- `install` кладёт файлы в новый кэш через `new Request(url, {cache: 'reload'})`.
  Без этого `addAll` берёт их из HTTP-кэша браузера, и в свежий кэш попадает
  старая версия — подъём `CACHE` перестаёт работать вообще.
- `data/*.json` идут «сначала сеть» через `fetch(url, {cache: 'no-store'})`.
  Без этого новый словарь не доезжает, хотя версию поднимать и не требуется.

## Бэкап прогресса

Настройки → «Выгрузить прогресс» / «Загрузить прогресс». Перед сменой
устройства или чисткой Safari — обязательно.
